# Central game authentication server

One Google OAuth and MongoDB Atlas backend for multiple games. Supported apps are defined in `apps.js`; clients cannot choose arbitrary MongoDB collections.

## Current apps

| App ID | Android deep link | MongoDB collection |
|---|---|---|
| `balloonpop` | `balloonpop://auth` | `balloonpop_users` |
| `candycraze` | `candycraze://auth` | `candycraze_users` |

Each collection has a unique index on Google's stable `sub` identifier, guaranteeing one record per Google account per app. The same person using both games receives one record in each game's collection.

## Render deployment

Create a Render Blueprint from `render.yaml`, then set:

- `MONGODB_URI`: Atlas connection string for the `game_auth` database
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: Google Web OAuth client
- `PUBLIC_URL`: Render service URL, such as `https://central-game-auth.onrender.com`
- `JWT_SECRET`: generated by the Blueprint

Add this authorized redirect URI in Google Cloud Console:

```text
https://central-game-auth.onrender.com/auth/google/callback
```

Apps begin login at `GET /auth/google?app=balloonpop` or `GET /auth/google?app=candycraze`. The issued session token is bound to that app and cannot read another app's collection.

For local development, copy `.env.example` to `.env` and run `docker compose up --build` or `npm install && npm start`.
